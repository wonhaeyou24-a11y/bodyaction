# KINETIC KABOOM — 손과 몸으로 놀자!

카메라 앞에서 손과 몸으로 즐기는 가족용 모션 아케이드 웹앱이에요. 영상은 이 기기 밖으로 나가지 않아요(브라우저 안에서만 인식).

## 실행

```bash
# 이 폴더에서 정적 서버를 켜고 http://localhost:8080 으로 접속 (카메라는 localhost/HTTPS에서만 켜져요)
python -m http.server 8080        # 또는 시작.bat (Windows)
```

- 인식은 MediaPipe(손/포즈)를 CDN과 Google 저장소에서 내려받아 써요. 처음 한 번은 인터넷이 필요해요.
- 주소 끝에 `?cpu` 를 붙이면 GPU 대신 CPU로 인식해요(GPU에서 인식이 안 될 때).
- 주소 끝에 `?seconds=8` 처럼 붙이면 한 판을 짧게(5~60초) 시험할 수 있어요.

## 게임 (13개)

손놀이(8): 풍선 팡팡 · 과일 닌자 · 우주 유성 막기 · 네온 벽돌깨기 · 쿵푸 펀치 도장 · 매직 드로잉 · 2인 풍선 대결 · 스피드 펀치 백  
몸놀이(5): 바위 피하기 · 아스트로 점프 러너 · 포즈 미믹 · 네온 노트 슬래시(리듬) · 모션 키퍼(골키퍼)

## 주요 기능

- **비동기 AI 엔진**: 손/몸 인식을 작업자(Web Worker)에서 돌려 인식 중에도 화면이 멈추지 않음 (`vision-worker.js`, `vision-client.js`). 게임 중 HUD에 실제 fps·초당 AI 횟수·인식 시간 표시. `?noworker`로 예전 방식
- 게임별 **등급 기준**(`main.js`의 `RANK_THRESHOLDS`) · 게임별 **TOP 10 순위표**(내 기록 / 가족 전체)
- **가족 프로필**: 사람마다 닉네임·아바타·기록을 따로 저장 (`profiles.js`)
- **첫 실행 안내**: 카메라 위치·밝기·손/몸 인식 확인 (`guide.js`)
- **온라인 대결 준비**: 비공개 방·초대 코드·같은 판 대결·재대결 구조 (`online/`, 지금은 같은 컴퓨터의 다른 탭끼리 연결. 자세한 건 `online/README.md`)

## 성능 점검 (속도·인식이 떨어지지 않았는지)

1. 게임 중 HUD에 실측값이 보여요: `화면 52fps · AI 17회/초 · 33ms 작업자 GPU` (고치기 전후로 비교)
2. 같은 조건으로 두 버전을 나란히 재려면 `test/browser-bench.js`를 쓰세요. 예전 커밋은
   `git worktree add /tmp/prev <커밋>` 후 다른 포트로 띄우고, 빈 페이지(`/assets/`)의 콘솔에서 실행해요.
   가짜 카메라 영상으로 프레임 처리 시간(평균·99%·최악)과 fps를 재서, **평균/99% 시간이 늘지 않았는지** 확인해요.
3. 기준값(2026-10-12, 가짜 카메라, 손 인식 게임): 프레임 평균 약 1ms, 99% 5ms 이하, 최악 25ms 이하


## 몸 움직임 녹화·채점 (개발·진단용)

실제로 해 보면 헷갈리는 판정을 숫자로 확인하는 도구예요. 영상은 저장하지 않고 관절 좌표만 저장해요.

1. 몸놀이 게임을 하는 중(또는 커스튬 룸)에 **F8** → 화면 안내(가만히 서기, 점프 5번, 앉기 5번, 좌우 기울이기, 펀치, 제자리 걷기)대로 약 100초 움직여요.
2. 끝나면 `kk-rec-날짜.json` 파일이 다운로드돼요.
3. `node test/replay.mjs 파일.json` → 동작별 인식률, 반응 시간, 엉뚱한 때 나온 오인식이 표로 나와요.
4. 판정을 고친 뒤 같은 파일로 다시 돌리면 좋아졌는지 바로 비교할 수 있어요. (`node test/replay.mjs`만 치면 가짜 사람으로 연습 실행)

## 오프라인 저장 (sw.js)

한 번 받은 게임·노래·음성·AI 파일(MediaPipe)을 이 기기에 저장해 두어서, 두 번째부터 빨리 열리고 인터넷이 불안정해도 열려요.

- 게임 코드는 인터넷이 되면 항상 새 것을 받아요(고친 게임이 바로 반영). 끊겼을 때만 저장본을 써요.
- 내 컴퓨터에서 개발할 때(`localhost`)는 꺼져 있어요. 시험하려면 주소 끝에 `?sw`.
- 저장을 모두 지우고 싶으면 `sw.js`의 `VERSION` 숫자를 올려요 (옛 저장분이 자동 삭제).
- 시험: `node test/sw.test.js`

## 네온 노트 슬래시: 곡 분석 기반 맵 (비트세이버식)

- `tools/music_map.py` 가 곡마다 박자 위치와 특징(세기·높낮이·구간 에너지)을 뽑아 `assets/music/<곡>.beats.json`(v2)에 저장해요. 곡을 바꾸거나 새로 넣으면 `python tools/music_map.py 곡이름` 으로 다시 만들어요 (ffmpeg 필요).
- `slash.js` 의 `buildMap` 이 그 특징으로 큐브 배치를 정해요: 높은 소리는 내려 베기·낮은 소리는 올려 베기, 센 박자는 양손 동시, 잔잔한 구간은 점(●)과 세로 베기·클라이막스는 대각선·가로, 같은 리듬은 같은 배치 반복, 손이 닿을 수 있는 거리만. 같은 곡은 항상 같은 맵이에요.
- 시험: `node test/slash.test.js --report` (10곡의 실제 분석 결과로 맵 품질을 확인해요)

## 인식 속도 자동 선택 (크기·GPU/CPU)

컴퓨터마다 가장 빠른 인식 방법이 달라요 (예: 손 인식 1번에 133ms → 초당 10번). 처음 24번의 인식 시간을 재서 70ms보다 느리면 후보(GPU·원본 / GPU·0.5배 크기 / CPU·0.5배 / GPU·0.35배)를 차례로 재 보고, 기준보다 20% 이상 빠른 것 중 가장 큰 크기(더 정확한 쪽)를 골라요. 결과는 이 기기에 기억하고(`kk_tune_hand/pose`), 주소에 `?retune`을 붙이면 다시 재요. 강제로 시험하려면 `?tune`. 게임 상단 표시 줄에 "(속도 재는 중)"과 "0.5배 크기"가 보여요.

## 인식 속도 진단 페이지 (diag.html)

게임과 따로, 이 컴퓨터가 몸·손 인식을 방법별(GPU/CPU, 영상 크기, 전달 방식)로 얼마나 빨리 하는지 재요. `diag.html`을 열고 카메라 앞에 서서 "측정 시작" → 약 1~1.5분 뒤 나오는 결과(JSON)를 복사해서 보내면 돼요. 게임 안에서는 느린데 여기서는 빠르다면 게임이 인식을 방해하는 것이고, 여기서도 느리면 컴퓨터(발열·절전·카메라) 문제예요. 계산 시험 점수가 시작·끝에 크게 다르면 컴퓨터가 뜨거워져 느려진 거예요.

## 가벼운 화면 모드 (자동)

같은 컴퓨터에서 게임 밖(`diag.html`)은 인식이 몸 18ms·손 25ms(초당 30번)인데 게임 안에서는 130~165ms(초당 5~10번)로 느려지는 일이 있었어요. 게임 화면이 GPU를 많이 써서 AI 인식과 다퉈요. 인식이 90ms를 넘게 5초 이어지면 자동으로 화면을 가볍게 해요: 1단계(번짐 그림자·배경 흐림 끄기 + 그리는 해상도 0.75배), 안 빨라지면 2단계(초당 30번만 그리기). 8초 지켜보고 인식이 15% 이상 빨라지면 유지(다음부터 처음부터 적용), 아니면 원래대로 되돌려요. 주소에 `?lite=1`/`?lite=2`로 강제, `?full`로 끄기, `?retune`으로 기억 지우기. 상단 표시 줄에 "가벼운 화면 ○단계"가 보여요.

## 엔진 선택: 예전 방식(classic) / 새 방식

기본은 **예전 방식(classic)**이에요. 2026-10-17 저녁에 새로 넣은 인식 개선(영상 찍힌 시각 사용·인식 끝나면 바로 재전송·속도 자동 선택(크기/GPU/CPU)·광선검 빠른 팔 추적기·손 끊김 보정·가벼운 화면 자동 모드)은 **주소 끝에 `?engine=new`를 붙였을 때만** 켜져요. 사용자 컴퓨터에서 새 방식이 더 느려졌다는 보고가 있어서 기본을 예전 방식으로 되돌렸어요. 예전 방식에서는 저장된 자동 선택·가벼운 화면 기록도 무시해요. (슬래시 규칙·화살표·곡 맵 등 게임 내용은 그대로예요.)
