# 온라인 대결 모듈 (`online/`)

혼자 하기는 그대로 두고, 친구와 **비공개 방(2명)** 으로 같은 판을 겨루는 기능을 위한 구조예요.
**게임 로직과 네트워크 로직이 분리**되어 있어서, 이 폴더를 통째로 빼도 게임은 그대로 돌아가요.
지금은 유료 서비스를 쓰지 않아요.

## 지금 되는 것

| 기능 | 상태 |
|---|---|
| 혼자 플레이 | 그대로 유지 (온라인 코드가 없어도 동작) |
| 비공개 방 만들기 / 초대 코드(`KABOOM-XXXXXX`)로 참가 | 됨 (2명) |
| 실시간 대결: 같은 시드 = 같은 판, 상대 점수 실시간 표시 | 됨 — 점프 달리기, 네온 노트 슬래시 |
| 끝난 뒤 점수 비교 · 승/패/무 · 상대가 나가면 기권승 | 됨 |
| 재대결 (둘 다 누르면 새 시드로 다시 시작) | 됨 |
| **같은 컴퓨터의 다른 탭/창** 끼리 연결 | 됨 (`LocalTransport`, BroadcastChannel) |
| **멀리 있는 친구와 연결** | 아직 — `Transport` 하나만 추가하면 됨 (아래) |

## 구조

```
main.js (게임)  ──bus 이벤트──▶  online/ui.js (화면)  ──▶  online/room.js (방 규칙)  ──▶  online/transport.js (연결)
      ▲                                  │
      └──── hooks.launch(mode, {seed}) ──┘            protocol.js : 메시지 약속 + 검사(sanitize)
                                                       rng.js      : 시드 난수, 초대 코드
```

- **게임(main.js)** 은 네트워크를 몰라요. 사건만 `bus`로 알려요: `game:start / game:score / game:end / game:quit`.
  온라인 쪽이 요청하는 건 `online:rematch` 하나뿐이에요.
- **room.js** 는 화면도 게임도 몰라요. `transport` 인터페이스만 써요. 그래서 `node online/test/room.test.js` 로 단독 테스트가 돼요.
- **같은 판 만들기**: 판의 내용을 정하는 곳(장애물·음표 배치)은 `rng()`(시드 난수)를 쓰고, 혼자 할 때는 `Math.random`이에요.
  꾸밈 효과(반짝이 등)는 `Math.random` 그대로예요.

## 규칙 (방장이 기준)

1. 방장 `create()` → 초대 코드 공유 → 손님 `join(코드)`
2. 손님 `setReady(true)` → 방장 `start()` (방장은 준비가 따로 필요 없어요)
3. 방장이 `{mode, seed, trackId}` 를 보내면 **두 명이 같은 시드로 동시에 시작** (각자 5초 준비 카운트다운)
4. 게임 중 `reportScore()` (0.25초마다), 끝나면 `finish(score)`
5. 둘 다 끝나면 `result` (`win|lose|draw`). 한 명이 나갔으면 남은 사람이 기권승(`forfeit`)
6. 재대결: 둘 다 `requestRematch()` 하면 방장이 새 시드로 시작

방은 2명까지, 게임이 시작된 뒤에는 새로 들어올 수 없어요. 손님이 로비에서 나가면 다른 사람이 들어올 수 있어요.
방장이 나가면 방이 닫혀요. 2초마다 ping을 보내고 7초 동안 소식이 없으면 나간 것으로 처리해요.

## 나중에 원격 연결을 붙이려면

`online/transport.js` 의 `Transport` 를 상속해서 4가지만 구현하면 `room.js`·`ui.js`·게임은 **그대로** 써요.

```js
class RemoteTransport extends Transport {
  async open(roomCode) { /* roomCode 채널에 연결 */ }
  send(obj)            { /* 같은 방 다른 사람에게 JSON 객체 전달 */ }
  close()              { /* 연결 끊기 */ super.close(); }
  // 받은 메시지는 this._deliver(obj) 로 넘기면 돼요
}
```

그리고 `createTransport(kind)` 에 `case "remote"` 한 줄만 추가하면 돼요. 후보 (무료로 가능한 것 위주):

| 방법 | 장점 | 주의 |
|---|---|---|
| **WebRTC + 손으로 코드 주고받기** | 서버가 전혀 필요 없어요 | 연결할 때 코드를 복사/붙여넣기 두 번 해야 해서 번거로움 |
| **PeerJS 무료 공개 중개 서버** | 설정이 가장 간단 | 공용 서버라 안정성 보장 없음, 일부 네트워크(회사/학교)에선 직접 연결이 안 될 수 있음 |
| **Supabase Realtime 무료 한도** | 안정적, 직접 연결이 막힌 곳에서도 동작(서버가 전달) | 프로젝트 생성이 필요하고, 무료 한도 정책은 만들기 전에 확인해야 함 |

초대 코드는 지금 6글자(약 8.9억 가지)예요. 원격으로 열 때는 **방장이 방을 닫으면 코드가 즉시 무효**가 되고,
같은 코드로 3번째 사람은 거절돼요(`join_full`).

## 새 게임을 온라인 대결에 추가하려면

1. 그 게임의 **판 내용을 정하는 난수**를 `Math.random()` → `rng()` 로 바꾸기 (스폰 시점/종류/위치 등. 꾸밈 효과는 그대로 둠)
2. 그 난수가 **프레임 속도와 상관없이** 같은 순서로 쓰이는지 확인 (스폰 타이머 안에서만 부르면 OK)
3. `online/protocol.js` 의 `ONLINE_MODES` 와 `online/ui.js` 의 `MODE_LABEL` 에 게임 id 추가

## 안전 / 한계

- 받은 메시지는 모두 `sanitize()` 를 거쳐요: 모르는 종류·잘못된 코드·범위를 벗어난 숫자는 버리고, 이름은 특수문자를 제거해요.
  아바타는 앱 안의 `assets/…` 이미지만 허용해요. 화면에는 `textContent`로만 보여 줘서 코드가 실행되지 않아요.
- **카메라 영상은 절대 보내지 않아요.** 오가는 건 점수와 방 상태뿐이에요.
- 점수는 각자의 기기에서 계산해요. 가족·지인끼리 쓰는 걸 전제로 해서 조작 방지는 하지 않아요.
  (온라인 랭킹처럼 낯선 사람이 겨루게 되면 서버에서 검증이 필요해요.)
